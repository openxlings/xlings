# 2026.8.22.1 —— 「抽象都在,调用点绕过它」

> 设计:`2026-08-22-cli-diagnostics-experience-design.md` · `2026-08-22-multi-frontend-architecture-design.md`

## 1. 一句话

用户报的是"提示不友好",查下去是同一个形状,而且这次它出现了**五次**:

> **需要的抽象已经在仓库里,调用点绕过它,于是抽象等于不存在。**

| | 抽象 | 调用点 |
|---|---|---|
| 多行消息 | `emit_line_` 会按标签宽度缩进续行 | 含 `\n` 的调用点 **0 个**;74 条续行各打一条同级日志 |
| 宽度契约 | `ui::layout` 完整 | 437 个 `log::` 在 core,够不着 |
| 配色语义层 | `theme::title/success/...` | 用了 **7** 次;颜色名访问器用了 **119** 次 |
| 语言设置 | `xlings config --lang` 全链路 + e2e | `set_language()` 无人调用,`tr()` **0** 处 |
| 交互选择器 | `ui/selector.cpp` 写好一年 | 零调用者(2026-07-29 调研已记过一次) |
| did-you-mean | `edit_distance_` | 只服务 5 类用户输入中的 1 类 |

所以这一轮的价值主要在**接线**,不在造新东西。新增的两个模块(`diag`、`libs/theme`)是为了让接线有地方接。

## 3. 顺带修掉的四个真缺陷

| | 症状 | 根因 |
|---|---|---|
| `xlings remove foo --agent` | 打印 `cancelled`、退出 **0**,包还在 | `--agent` 用 `defaultValue` 回答一切,而两个确认的默认方向**相反** |
| `xlings subos new x --from y` | 成功后**零输出** | 一个 DataEvent、零消费者、成功路径无 log 兜底 |
| `xlings install <打错的名字>` | 一句话被拆成几条独立的"错误" | 折行按行发 `log::error` |
| `lang` / `auto` | 永远只能得到 `en` | `std::locale("")` 在 musl 静态和 glibc 上都抛异常,被 catch 成 `"en"` |

最后一条值得单独说:**"系统真是英文"和"探测彻底失败"输出一模一样**。一个自带、且永远发现不了的 bug。

## 4. 两处推翻了自己 —— 都是跑既有测试发现的,不是读代码发现的

### 4.1 交互选择器必须是 opt-in

我按"默认 true"实现了 `use <name>` 的行内选择器。跑 **E2E-48**(`non_interactive_contract_test.sh`)才发现它是 2026.7.30 的既有决定 + 设计文档,**N3 专门分配真 pty** 断言这件事不许发生。

理由写在那份文档里,而且是对的:

> whether a human is at the keyboard is not detectable, so it must not decide semantics

agent 和自动化经常分配 pty,所以"是不是终端"恰好把**阻塞分支**交给最不能回答的一批调用者。我的门控是 `!agent_mode && stdout_is_terminal()` —— 同一类信号,同一个缺陷。

改成 `tui.interactive` 默认 **false**。存下来的偏好和 tty 性质不同:它是一个**承诺**,由那个会坐在键盘前的人做出。

### 4.2 拒绝确认不能一刀切

我让所有"无人可问"的确认都报错。E2E-48 的 install 用例立刻红了 —— `install <pkg>`(不带 `-y`、stdin 关闭)完成是**被断言的既有行为**。

重新看那两个默认值:

```
confirm_install  "y"  -> 继续。可观测,而且是文档化行为。
confirm_remove   "n"  -> 打印 cancelled、退出 0、包还在。谎报。
```

**缺陷不是"猜",是"猜否并称之为成功"。** 策略因此交给调用方声明:install/update `Proceed`,remove `Refuse`。

## 5. 新增

- **`libs/theme`** —— 独立 mcpp 成员包,零依赖,拥有 `Rgb`/`Background`。九个**角色**槽,126 个调用点改名。内置默认与改名前**逐字节相同**(单测直接对着 `palette` 断言),像素零变化。自带 `mono` / `high-contrast`。`theme` 存**路径引用**,所以项目能自带配色 —— 和它自带索引源同一个机制。
- **`--ui-mode cli|tui`** + `--theme` + `--interactive` + `--background`,全部复用 `--mirror` 那条链路。**降级必须说出来**。
- **`xlings-gui`** —— 独立二进制 + workspace 成员。被实测逼出来:静态 musl 的 `dlopen` 是 stub,GLFW/GL 驱动都靠它。这条约束属于 `xlings` 而**不属于 Linux**(图形栈在索引里已闭环)。默认不编。

## 6. 两个平台陷阱(本地 clang gate 抓到)

| | 症状 | 修法 |
|---|---|---|
| `"\x01cannot-ask"` | clang「hex escape sequence out of range」—— `\x` 吃掉后面所有 hex 位,读成 `\x01ca` | 拆成两个相邻字面量 |
| `std::println("{}", x)` 无 stream | clang 把格式串本身当参数实例化 | 显式写 `stdout` |

第二条尤其值得记:那五个 `std::println` **一直都在**,clang 一直编得过 —— 给同一个 TU 加一个 `import` 就翻了。**这不是从文件本身能预测的**,所以修法是"点名 stream",不是"注意 import 顺序"。

本地 gate:`mcpp build --toolchain llvm@20.1.7`,~40s,和 macOS CI 用同一个 llvm payload。

验证 main 时第一次做错了:对着干净工作树跑 `git stash`(什么都没 stash),于是"验证 main"其实又测了一遍自己的分支,得出相反结论。用 worktree 重做才对。
