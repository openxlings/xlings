# 2026.8.22.3 —— 「问该问的,以及把模块放回它该在的位置」

> 设计:`2026-08-22-interaction-theme-and-layout-design.md`
> 上一轮:`2026-08-22-release-2026.8.22.2-notes.md`

## 1. 一句话

用了一周 2026.8.22.1/.2 建出来的东西,发现六个已发布缺陷 —— **其中两个是那两次发布自己引入的** —— 以及三处不能再漂移下去的结构。

## 2. 行为变化(升级后立刻会感觉到的)

| | 改前 | 改后 |
|---|---|---|
| `xlings install foo`(无 `-y`) | 不问,直接装 | **会问一次**。这是 `-y` 一直声明的行为 |
| `xlings remove foo`(无 `-y`) | `[error] there is nobody to ask`,exit 2 | 会问一次;终端上答得了 |
| `xlings use gcc`(不带版本) | 候选恰好 1 个时**切换**,否则列出 | **恒为列出**。切换要指名版本 |
| `xlings config` | `theme`/`interactive` 未设置时整行消失 | 每行都显示生效值,并标 `(default)` |
| 中文环境 | 全英文 | 帮助与 `config` 标签为中文 |

`use <name>` 那条是唯一可能影响脚本的:依赖它做激活的脚本要补版本号 —— 而它们本就该补,因为候选多于一个时那条命令从来什么也没做。

## 3. 六个缺陷

| | 症状 | 根因 |
|---|---|---|
| `install <打一半的名字>` | 打印 `cancelled`,**exit 0**,没人被问也没人取消 | `select_package` 判断返回值为空即取消,而 cannot-ask 哨兵不是空,落进了匹配不到的查找 |
| `remove` 在终端上 | `there is nobody to ask` —— 而用户就在键盘前 | 确认框挂在选择器的 opt-in 偏好上,于是从不发问,`-y` 记录着一个不存在的提问 |
| 失败的 `remove` | 动作是 `install it here` | 2026.8.22.1 复用 `not_in_subos` 取措辞,连同它为「你想**用**这个包」写的动作一起继承了 |
| `use <name>` | 一条命令两种语义 | `--help` 写着「省略即列出」,而代码在候选为 1 时切换。候选数是「已 opt-in 到**本** subos 的版本数」,用户看不见 |
| `config --theme mnoo` | 回显成功,此后每条命令都警告 | 同一函数里 `--ui-mode` 和 `--interactive` 都校验并 exit 2,只有它不校验 |
| `xlings config` | 未设置的行消失 | 同一张表混了「配置了什么」与「实际是什么」 |

## 4. 三处不能再漂移的结构

**`prompt()` 用一个 `std::string` 编码三种结局** —— 值、`""`(取消)、哨兵(没人可问)。三种里有两种看起来像正常值,只处理其中一种照样编过,`select_package` 就是这么坏的。改成 `std::variant<Chosen, Cancelled, NobodyToAsk>`,`std::visit` 少写一个分支即编译错误。**必须是 variant 而不是 enum**:本仓库 `cxxflags` 里没有 `-Werror`,枚举漏分支只会是警告。

**三套问法在问用户。** `utils::ask_yes_no` 直读 `std::cin`,绕过 `--interactive` 和 `--agent`,对 `xlings interface` 完全不可见,且 EOF 时返回默认值 —— 而默认值随方向变(`!downgrade`),于是管道里的 `self install` 升级自动同意、降级自动拒绝,都不出声。删除,合并成一条线。

**`xlings config` 有两个渲染实现。** `cli.cpp` 自建了 `xself::cmd_config` 的近似副本,而只有副本可达。查了三轮才发现:我对被调用不到的那份的修改编进了二进制却毫无效果。两份表已经在漂移。

## 5. 两层门控

| 层 | 覆盖 | 门控 | 无人可答时 |
|---|---|---|---|
| **确认**(y/n,有默认值) | install / remove / update / self install | `stdin` 是终端 **且** 非 `--agent` | 调用方声明的 `WhenNobodyCanAnswer` |
| **选择**(列表,无默认值,会阻塞) | 版本选择器、包名消歧 | 上述 **且** `tui.interactive` | 完整候选面板 |

门控看 **stdin** 而非 stdout:`install foo | tee log` 的 stdout 是管道而键盘前有人。2026.7.30 那条「pty 不足以证明有人在」的决定仍然成立 —— 它针对的正是会阻塞的那一层。

## 6. 目录

```
apps/gui/              modules/platform/      → cancellation
modules/json/          modules/i18n/          → platform
modules/sha256/        modules/tinyhttps/     → mcpplibs.tinyhttps(包名 xhttp)
modules/cancellation/  modules/theme/         → json 的头目录
src/                   core / cli / ui / runtime —— 尚未拆出的部分
```

`platform` 3230 行、被 211 个 TU 中的 81 个 import,而它自己的依赖只有一条。**广度在上游,决定能否抽出的是它依赖什么。**

被迫解决的两处耦合:`tinyhttps` 为一行 `log::debug` 依赖了根包(成员不能依赖根包,改为记录代理供调用方自行报告);它的裸名与所包装的 `mcpplibs.tinyhttps` 冲突,mcpp 的依赖名是单一命名空间。

**`[build]` 不被成员继承** —— 只有 `[toolchain]` 和 `[target.<triple>]` 会。成员少一个宏不会失败,只会编出另一份语义:Windows 上缺 `-DUNICODE` 会静默选中 ANSI 版 Win32 API。移动前逐 flag 核对过(platform 一个都不需要:显式 `W` API、零 TCHAR、不用 libarchive、无第三方头),结论写进了它的 `mcpp.toml`。

## 7. 移动静默收窄了一个测试

`test_windows_header_hygiene.py` 只扫 `ROOT/src`,而 `<windows.h>` 正好全在 `platform` 里。不修的话它会继续输出 `ok`,检查的文件从 **10 个变成 4 个** —— 而"找到的文件更少"和"违规更少"在输出上完全一样。

这是本轮在治的形状,由本轮的移动亲手制造。现在扫 `src`+`modules`+`apps`,且一个文件都找不到时失败。

## 8. i18n

旧表 36 条消息、中英齐备、**零调用点** —— 所以「xlings 没有中文」是准确的,尽管每条译文都在。它也不可能扩展:枚举被每次新增消息改动,而加一门语言意味着给每一行加一列。

`modules/i18n`,一语言一文件:`en.cppm` 是基底且必须完整,其余只写差异并**按 key** 回退。与主题对内置默认的关系同构。

**内置而非文件交付**(与主题相反),判据是用户是否会作为作者去编辑它:`mono.json` 存在就是为了被复制修改,译文表不是。内置省掉整条「打包→拷贝→读盘→解析」链路和它的每一种失效方式。

已覆盖:帮助章节标题、子命令与选项描述、`config` 字段标签。规则是**能敲进终端的东西不翻** —— 命令名、旗标、占位符、`XLINGS_HOME`、以及所有 `std::format` 参数;解释它的话翻。

## 9. 主题改为数据

`mono`/`high-contrast` 曾是 C++ 原始字符串字面量,打包时由 `self init` 写到盘上,进 tarball,由索引配方拷进 home,运行时再读回来 —— 一份两端都是配置文件的内容,中间绕了源码一圈。现在是源码树里的 `config/themes/*.json`,由 release 脚本拷贝。

这把「内置主题如何到达一个 home」的**三个**回答者塌缩成一个。它们本会打架:被配方升级过的 home 再被旧二进制跑一次,旧的内嵌副本会写回覆盖较新的文件。

`default` 仍编译进二进制。`self install` 现在**按文件**在升级时也刷新那两个名字,所以用户放在同目录的主题不受影响。三个 release 脚本新增了「主题在产物里」的断言 —— 内嵌时期这条链路没有任何检查,而 xim-pkgindex#672 正是因为同一条链路的另一环静默丢了它们才被发现的。

## 10. 自我 review 抓到的两个缺陷(本分支自己制造的)

让确认框真的会问,把 `ui::confirm` 里两个休眠的性质变成了活缺陷:

- **提问写在 stdout。** `remove foo > log` 且 stdin 是终端时,问题进了文件,用户看到一个"卡住"的进程 —— 它确实在等他。改到 stderr。
- **EOF 返回默认值。** 又一次「替人猜答案」,而且默认值随调用方而变。改成 `std::optional<bool>`,nullopt → `Cancelled`。

E2E-48 的 N8 覆盖这两条。它**不能用现成的 `RUN_PTY`** —— 那个 helper 用 `script`,会把 stdout/stderr 合并成一条流,而那正是被测的区别;N8 只给 stdin 分配 pty,stdout/stderr 各自独立。改回 stdout 版本验证过它确实会失败。

## 13. 发布过程本身抓到的东西

第一次发布尝试失败在 `candidate-windows-x86_64`,而这一次失败连着挖出三层:

**其一,我的回归。** `self install` 的所有确认在无人可答时被我一刀切拒绝,但同版本重装是幂等的 —— 脚本化的 `xlings self install` 就是这个意思。改成按问题声明策略,并引入第三种结局:

| 问题 | 无人可答 | 理由 |
|---|---|---|
| 同版本重装 | `Proceed` | 幂等 |
| 覆盖 data/subos | `Decline` | 可选项;拒绝它不终止命令,报 Note 走 stdout |
| 升级 | `Proceed` | 无人值守也安全 |
| 降级 | `Refuse` | 往回走要有人明说 |

`Decline` 不是 `Refuse` 的别名。把一个**可选项**的拒绝报成 error 错了两次:声称失败而其实没有,以及写到 stderr —— 而 PowerShell 会把 native 命令的 stderr 转成终止错误,于是一次**成功**的 `self install` 被判为失败。这就是 Windows 红的直接原因。

**其二,candidate smoke 从来没测过它声称要测的东西。** 两侧都断言"覆盖正在运行的二进制"(#473),而"positive evidence"用的是 `install:` —— 那一行在**取消**的输出里同样存在;旧的 `ask_yes_no` 在 EOF 总是取消。所以它一直在为一次取消的退出码鼓掌。用两份真实日志交叉验证:

| 日志 | 旧断言 | 新断言 |
|---|---|---|
| 装完了 | PASS | PASS |
| 取消了 | **PASS** | FAIL |

改用 `- ok`(只有跑完的路径才打印)并显式拒绝 `cancelled`。发布后从 CI 日志确认:`- ok` 出现 1 次、`cancelled` 0 次 —— 这个测试第一次真的执行了。

**其三,`fail` 被调用但从不存在。** `smoke.sh` 里唯一一处断言调用它,真触发只会得到 `command not found`:红是红了,原因全丢 —— 而这是个只在发布时才跑的 job,日志就是全部。已定义。

## 14. 我在这次发布里犯的错

**用 `ls -d build/xlings-* | head -1` 选包,字典序让半年前的 `0.4.40` 排在 `2026.8.22.3` 前面。** 那个旧二进制早于「`self install` 尊重 `XLINGS_HOME`」的修复,于是无视我传的变量,装进了开发者的真实 home,把入口二进制降级并清掉了 `config/themes/`(已恢复;`data/` 与 45 个 subos 未被触碰,因为覆盖它们是另一个默认为否的确认)。

教训有两条,都已写进 `.agents` 之外的长期记忆:

1. **绝不按 glob 顺序选构建产物** —— 不用 `head -1`、不用 `tail -1`、不用 `ls -t`。按版本号拼出确切路径,并在运行前先核对 `--version`。
2. **验证性 `self install` 要同时重定向 `HOME` 与 `XLINGS_HOME`。** 只设后者等于假设被测二进制尊重它,而这恰恰是陈旧二进制会打破的假设;`HOME` 一并重定向后,`~/.xlings` 的回退也落在 scratch 里。

顺带一提:同一天我在自己的验证脚本里也造了两个"失败与成功产出相同输出"的检查(`grep -c … || echo 0` 产生 `"0\n0"`;把一次瞬时读数当稳定状态)。和本轮在产品里修的三个缺陷是同一形状,区别只在于产品的会误导用户,我的会误导我自己。
