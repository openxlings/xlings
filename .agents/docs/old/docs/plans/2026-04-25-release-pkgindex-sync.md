# 方案：xlings release 后自动同步 xim-pkgindex

**问题：** 现在 xlings 出新版（`Release` workflow 创建 `v0.4.x` tag + 三平台 artifact）之后，`xim-pkgindex/pkgs/x/xlings.lua` 仍然停在 0.3.1。这意味着任何 0.4.x 用户跑 `xlings self update` 都升级不到新版（甚至会被 `xim install xlings@latest` 拉回 0.3.1），整套自升级机制名存实亡。

本方案：让 release workflow 完成后**自动**把新版本注册进 `xim-pkgindex`。

## 一、整条自升级链路（要 sync 的不止一处）

```
xlings repo (d2learn/xlings)
  release.yml → tag v0.4.3 + 3 个 artifact 上传到 d2learn/xlings/releases ✅ 已有

xim 安装路径（用户跑 xlings install xlings@latest）
  ① 读 xim-pkgindex/pkgs/x/xlings.lua 的版本表          ← 待同步
       linux/macosx/windows 各自 xpm 表，加 ["0.4.3"] = "XLINGS_RES"
       latest = { ref = "0.4.3" }
  ② "XLINGS_RES" 解析到资源服务器（GLOBAL: github.com/xlings-res）
  ③ 拉 https://github.com/xlings-res/xlings/releases/download/0.4.3/...  ← 待同步
       artifact 必须出现在 xlings-res/xlings 这个镜像 repo 的 release 上
```

**两个仓库都要同步**，不然 xlings.lua 改了但 artifact 没镜像，`xim install` 会 404。

实测：
- `gh release list -R xlings-res/xlings` → 只有 0.3.0 / 0.3.1，0.4.x 全无
- `xim-pkgindex/pkgs/x/xlings.lua` → latest=0.3.1

## 二、可行性

| 维度 | 结论 |
|---|---|
| **xim-pkgindex 是机械改 `.lua`** | ✅ 改动只两处：xpm.{linux,macosx,windows} 各加一行 `["X.Y.Z"] = "XLINGS_RES"` + 改 `latest = { ref = "X.Y.Z" }`。无 SHA256 维护（XLINGS_RES 是 sentinel，由 xim 运行时解析）。 |
| **xlings-res/xlings 镜像 release** | ⚠️ 需要把 d2learn/xlings 的 3 个 artifact 复制一份发到 xlings-res/xlings 的 release。GitHub 跨仓发布 release 需要 PAT 或 GitHub App 授权。 |
| **PAT 风险** | 中等 —— 需要一个 token 同时有 `xim-pkgindex` write 和 `xlings-res/xlings` write。建议用 GitHub App 或细粒度 PAT 限定只这两个仓库的 contents:write。 |
| **幂等** | ✅ 重跑同版本应当 no-op；用脚本判断 "version already in lua" / "release already exists" 跳过。 |
| **失败模式可见** | ✅ 同步若挂了，现状最坏就是退化到今天的"手动维护"，不影响 d2learn/xlings 的 release 本身。 |

## 三、实施方案

### 3.1 新增一个 sync 作业到 xlings/release.yml

`create-release` 之后串一个 `sync-pkgindex` job，依赖 `[create-release]`。

```yaml
sync-pkgindex:
  needs: [create-release]
  runs-on: ubuntu-latest
  steps:
    - name: Determine version
      id: ver
      run: echo "version=$(sed -n 's/.*VERSION = "\([^"]*\)".*/\1/p' src/core/config.cppm | head -1)" >> "$GITHUB_OUTPUT"

    # ① 镜像 artifact 到 xlings-res/xlings
    - name: Mirror artifacts to xlings-res/xlings
      env:
        GH_TOKEN: ${{ secrets.RES_MIRROR_PAT }}   # PAT/App with contents:write to xlings-res/*
      run: |
        VER="${{ steps.ver.outputs.version }}"
        # 从 d2learn/xlings/releases/v$VER 下载 3 个 artifact
        for f in xlings-${VER}-linux-x86_64.tar.gz xlings-${VER}-macosx-arm64.tar.gz xlings-${VER}-windows-x86_64.zip; do
          gh release download "v${VER}" -R d2learn/xlings -p "$f" -O "/tmp/$f"
        done
        # 在 xlings-res/xlings 创建（或追加）同 tag 的 release
        if ! gh release view "v${VER}" -R xlings-res/xlings >/dev/null 2>&1; then
          gh release create "v${VER}" -R xlings-res/xlings --title "${VER}" --notes "Mirror of d2learn/xlings v${VER}"
        fi
        gh release upload "v${VER}" -R xlings-res/xlings /tmp/xlings-${VER}-*.{tar.gz,zip} --clobber

    # ② 在 xim-pkgindex 仓库开 PR 改 xlings.lua
    - name: Patch xim-pkgindex/pkgs/x/xlings.lua
      env:
        GH_TOKEN: ${{ secrets.PKGINDEX_PAT }}
      run: |
        VER="${{ steps.ver.outputs.version }}"
        gh repo clone d2learn/xim-pkgindex /tmp/xim-pkgindex -- --depth 1
        cd /tmp/xim-pkgindex
        python3 - <<PY
        import pathlib, re, sys
        p = pathlib.Path("pkgs/x/xlings.lua")
        s = p.read_text()
        # 1) update latest = { ref = "X.Y.Z" } in all 3 platform tables
        s = re.sub(r'(\[\"latest\"\] = \{ ref = ")[^"]+(" \})',
                   rf'\g<1>${VER}\g<2>', s)
        # 2) insert new ["X.Y.Z"] = "XLINGS_RES" if missing
        for plat in ("linux", "macosx", "windows"):
            block_re = rf'({plat} = \{{\s*\[\"latest\"\] = \{{ ref = "[^"]+" \}},)'
            insertion = rf'\1\n            ["${VER}"] = "XLINGS_RES",'
            if f'["${VER}"]' not in s.split(f'{plat} =')[1].split('}}')[0]:
                s = re.sub(block_re, insertion, s, count=1)
        p.write_text(s)
        PY

        git config user.name  "xlings-release-bot"
        git config user.email "release@xlings.d2learn.org"
        BR="release/xlings-${VER}"
        git checkout -b "$BR"
        git add pkgs/x/xlings.lua
        git commit -m "xlings: register v${VER}"
        git push origin "$BR" --force-with-lease
        gh pr create -R d2learn/xim-pkgindex --base main --head "$BR" \
          --title "xlings: register v${VER}" \
          --body "Auto-generated by xlings/release.yml after publishing v${VER}."
        gh pr merge --squash --auto -R d2learn/xim-pkgindex "$BR"  # 设了 auto-merge 时就直入
```

### 3.2 直接 push vs PR

| 方案 | 优 | 劣 |
|---|---|---|
| **直接 push 到 main** | 极简，1 步到位；不需要 review；同步即生效 | 一旦 patch 脚本写错，main 直接污染；事后修代价大 |
| **开 PR + auto-merge**（推荐）| 留 trace（可回溯）；分支保护可强制；patch 失败 PR 不合 | 多一个 PR-cycle 时间（几分钟） |

我倾向 PR + `gh pr merge --squash --auto`。如果 xim-pkgindex 配了 required CI（pkgindex-build / 验证 lua 加载），auto-merge 会等它绿才合 —— 自动把"Lua 写错"挡在外面。

### 3.3 PAT / 权限

需要两个 secret 加到 d2learn/xlings 仓库：

| Secret | Scope | 用途 |
|---|---|---|
| `RES_MIRROR_PAT` | xlings-res/xlings → contents:write | 镜像 release artifact |
| `PKGINDEX_PAT` | d2learn/xim-pkgindex → contents:write + pull-requests:write | 开 PR 改 xlings.lua |

强烈建议用 **GitHub App + installation token**，比裸 PAT 安全（可吊销、可审计、可范围）。

### 3.4 幂等 + 重试

- 脚本里检查 `["X.Y.Z"] = "XLINGS_RES"` 是否已存在（grep 跳过）
- `gh release create` 改成 `gh release view ... || gh release create ...`
- `gh release upload --clobber` 允许重传

允许 `release.yml` 失败一半再重跑也不会出双份。

### 3.5 失败时的自我披露

加一个失败 step（`if: failure()`）写一个 GitHub issue 自己提醒：

```yaml
- name: Notify maintainers on sync failure
  if: failure()
  uses: actions/github-script@v7
  with:
    script: |
      github.rest.issues.create({
        owner: 'd2learn', repo: 'xlings',
        title: 'release/sync failed for v${{ steps.ver.outputs.version }}',
        body: `Run: ${context.serverUrl}/${context.repo.owner}/${context.repo.repo}/actions/runs/${context.runId}`
      })
```

这样维护者能及时知道"release 出了但 pkgindex 没同步"。

## 四、工作量估算

| 项 | 文件 | LOC |
|---|---|---|
| `sync-pkgindex` job 加到 release.yml | `.github/workflows/release.yml` | ~80 |
| Lua patcher（python 嵌入或独立脚本） | inline 或 `tools/sync_pkgindex.py` | ~40 |
| 在仓库设 secret `RES_MIRROR_PAT` / `PKGINDEX_PAT` | GitHub UI | 2 个 |
| `docs/release-process.md` 写下流程图 | 文档 | ~30 |
| **总** | | **~150 行 yaml/python + 2 个 secret** |

## 五、需要你拍板的几件事

1. **走直接 push 还是 PR + auto-merge？** —— 我倾向 PR + auto-merge（有 trace）。
2. **token 用 PAT 还是 GitHub App？** —— 我倾向 App（更安全、可审计），但 PAT 起步更快。
3. **scope 是否包含 xlings-res/xlings 镜像？** —— 不做镜像的话只改 xim-pkgindex 没用（artifact 在 xlings-res 那边还是空的）。要么做，要么改 xlings.lua 让它直接指向 d2learn/xlings 的 release URL（绕开镜像层）。
4. **失败回滚需求？** —— 当前方案是"开 PR 等审 / auto-merge 失败留 PR"，没主动 revert。我觉得够了；要更激进可以加。

## 六、补一刀：兜底版本 check

即使做了自动同步，也建议给 xlings 二进制加一个**独立的 GitHub releases API 兜底通道**（前一份分析里提的 `xlings self check`）：直接打 `api.github.com/repos/d2learn/xlings/releases/latest` 拿 tag，跟 `Info::VERSION` 比。这样：

- 不依赖 xim-pkgindex 同步是否及时
- 用户跑 `xlings self check` 能立刻看到"你 0.4.3，最新 0.5.1，跑 xlings self update 升"
- xim-pkgindex 同步出问题时，至少 check 还能告诉用户"该升了"

这两件事互不冲突，可以并行做。本文档主要谈第一件（自动同步）。

## 七、推荐顺序

1. **先做** xlings-res/xlings 镜像 + xim-pkgindex 自动同步（本方案 3.1-3.5）—— 解决 0.4.x 的 `self update` 不能用的根本问题。
2. **再做** xlings 二进制 `self check` 走 GitHub releases API（独立分支、独立 PR）—— 兜底 + 增加用户感知。
3. **最后再考虑** 启动时 hint / 后台 cron 之类的"主动提醒"。
