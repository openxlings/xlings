# xlings release & self-update 架构

**这份文档归档当前架构问题、止血方案、以及长期演进路线。**

## 一、当前架构

```
┌─────────────────────────────────────┐
│ d2learn/xlings                      │
│   release.yml → tag v0.4.x          │   ← 唯一 source of truth
│   + 3 个 artifact 上传 GitHub       │      （本仓库 GitHub releases）
└──────────────┬──────────────────────┘
               │ ❌ 现状无任何自动同步机制
               ▼
┌─────────────────────────────────────┐
│ xlings-res/xlings (镜像 / CN 加速)  │
│   预期：和 d2learn/xlings 同 tag    │
│   现状：停在 0.3.1                  │
└─────────────────────────────────────┘

┌─────────────────────────────────────┐
│ d2learn/xim-pkgindex                │
│   pkgs/x/xlings.lua 版本表          │
│   xpm.{linux,macosx,windows} =      │
│     ["X.Y.Z"] = "XLINGS_RES"        │   ← XLINGS_RES 是 sentinel，
│   latest = { ref = "..." }          │      运行时由 xim 解析到镜像 URL
│   现状：停在 0.3.1                  │
└─────────────────────────────────────┘

xlings self update 路径：
  → xim update（拉 xim-pkgindex）
  → xim install xlings@latest -y
  → 读 xlings.lua xpm 表，构造 URL
  → URL = XLINGS_RES + /xlings/releases/download/<tag>/<artifact>
  → 解析 XLINGS_RES → github.com/xlings-res（GLOBAL）/ gitcode.com/xlings-res（CN）
```

## 二、问题诊断

3 处需要同步：

1. d2learn/xlings 出 release（build artifact + 打 tag）—— 自动，OK
2. 把 artifact 镜像到 xlings-res/xlings —— **手动维护，已欠债 4 个版本**
3. 把版本号加到 xim-pkgindex/xlings.lua —— **手动维护，已欠债 4 个版本**

任何一处掉链子，self-update 就 broken。所以现在 0.4.x 用户跑 `xlings self update` **不会升级**（甚至会被 xim 解析到 0.3.1）。

## 三、Phase A — 止血（目标：~150 行 yaml/python）

**不改架构**，让 release.yml 完成 ② ③ 两步同步，从「完全不能 self-update」修到「能用」。

### 改动清单

`.github/workflows/release.yml` 加一个 `sync-pkgindex` job，依赖 `[create-release]`：

```yaml
sync-pkgindex:
  needs: [create-release]
  runs-on: ubuntu-latest
  steps:
    - name: Determine version
      id: ver
      run: echo "version=$(sed -n 's/.*VERSION = \"\([^\"]*\)\".*/\1/p' src/core/config.cppm | head -1)" >> "$GITHUB_OUTPUT"

    # ① 镜像 artifact 到 xlings-res/xlings
    - name: Mirror artifacts to xlings-res/xlings
      env:
        GH_TOKEN: ${{ secrets.RES_MIRROR_PAT }}
      run: |
        VER="${{ steps.ver.outputs.version }}"
        for f in xlings-${VER}-linux-x86_64.tar.gz xlings-${VER}-macosx-arm64.tar.gz xlings-${VER}-windows-x86_64.zip; do
          gh release download "v${VER}" -R d2learn/xlings -p "$f" -O "/tmp/$f"
        done
        gh release view "v${VER}" -R xlings-res/xlings >/dev/null 2>&1 \
          || gh release create "v${VER}" -R xlings-res/xlings --title "${VER}" --notes "Mirror of d2learn/xlings v${VER}"
        gh release upload "v${VER}" -R xlings-res/xlings /tmp/xlings-${VER}-*.{tar.gz,zip} --clobber

    # ② 在 xim-pkgindex 仓库开 PR 改 xlings.lua
    - name: Patch xim-pkgindex/pkgs/x/xlings.lua
      env:
        GH_TOKEN: ${{ secrets.PKGINDEX_PAT }}
      run: |
        VER="${{ steps.ver.outputs.version }}"
        gh repo clone d2learn/xim-pkgindex /tmp/xim-pkgindex -- --depth 1
        cd /tmp/xim-pkgindex
        # python 脚本 patch xlings.lua
        # 1) ["latest"] = { ref = "X.Y.Z" } 改成新版本
        # 2) 三个平台表分别加 ["X.Y.Z"] = "XLINGS_RES"（已有就跳过）
        git checkout -b "release/xlings-${VER}"
        git add pkgs/x/xlings.lua
        git commit -m "xlings: register v${VER}"
        git push origin "release/xlings-${VER}" --force-with-lease
        gh pr create -R d2learn/xim-pkgindex --title "xlings: register v${VER}" \
          --body "Auto-generated by xlings/release.yml after publishing v${VER}."
        gh pr merge --squash --auto -R d2learn/xim-pkgindex "release/xlings-${VER}"

    - name: Notify maintainers on failure
      if: failure()
      uses: actions/github-script@v7
      with:
        script: |
          github.rest.issues.create({
            owner: 'd2learn', repo: 'xlings',
            title: 'release/sync failed for v${{ steps.ver.outputs.version }}',
            body: `Run: ${context.serverUrl}/${context.repo.owner}/${context.repo.repo}/actions/runs/${context.runId}`
          })
```

### 需要的 secret

| Secret | Scope | 用途 |
|---|---|---|
| `RES_MIRROR_PAT` | xlings-res/xlings → contents:write | 镜像 release artifact |
| `PKGINDEX_PAT` | d2learn/xim-pkgindex → contents:write + pull-requests:write | 开 PR 改 xlings.lua |

强烈建议用 GitHub App + installation token，比裸 PAT 安全。

### 设计抉择（A 阶段需要拍板的）

1. **直接 push 到 main vs 开 PR + auto-merge** —— 推荐 PR + auto-merge（有 trace、可被 xim-pkgindex 的 CI 拦下不合格 patch）
2. **PAT vs GitHub App** —— 推荐 App
3. **xlings-res 镜像要不要做** —— 当前 xlings.lua 用 `XLINGS_RES` sentinel，必须做；若改 xlings.lua 直接指 d2learn/xlings 的 release URL（绕开镜像），可以省这一步但失去 CN 加速
4. **失败回滚** —— 当前是「失败留 PR」，够用

## 四、长期方案（Phase B / C）—— 解决"为什么要同步"

Phase A 是"在三处同步它们"。真问题是"为什么这三处需要同步"。一旦让 xim 从 source repo 自动发现版本，整个同步问题消失。

### Phase B（一两个月）— 包描述自描述 + 二进制端兜底

**B1：xim-pkgindex/pkgs/x/xlings.lua 不再列硬编码版本**

```lua
package = {
    name = "xlings",
    type = "package",
    repo = "https://github.com/d2learn/xlings",

    xpm = {
        source = "github_releases",   -- 新增 discovery 模式
        repo   = "https://github.com/d2learn/xlings",
        artifact_pattern = "xlings-{version}-{os}-{arch}.{ext}",
        ext_by_os = { linux = "tar.gz", macosx = "tar.gz", windows = "zip" },
        -- 可选：固定版本黑名单
        skip_versions = {},
    },
}
```

`xim install xlings@latest` 时：
- xim 看到 `source = "github_releases"`
- 调 `https://api.github.com/repos/d2learn/xlings/releases/latest`
- 拿到 `tag_name = v0.4.3`，按 pattern 拼出 asset 名和 URL
- 下载（可走 ghproxy / jsdelivr / 直连 github，按 mirror 配置）

xim-pkgindex 里**不再持有版本数据**。新版本出现时，xim 下次 install 自动可见，不需要 xim-pkgindex 跟随更新。

**B2：xlings 二进制端 `xlings self check`**

不依赖 xim-pkgindex，直接打 `api.github.com/repos/d2learn/xlings/releases/latest`，比 `Info::VERSION`：

```
$ xlings self check
You are on 0.4.3.
Latest is 0.5.1 (released 2026-05-12).
Run `xlings self update` to upgrade.
```

如果同时引入了 B1，self update 也会从 source 实时拿；如果 xim 还没引入 discovery，self check 至少能告知用户该升了。

**B 阶段成本估算**

| 项 | LOC |
|---|---|
| xim 引擎加 `source = "github_releases"` discovery | ~150 |
| xlings.lua 迁移到自描述 | ~10（删大半，加几行 source 配置） |
| xlings 二进制端 self check | ~80 |
| 文档 + 测试 | ~100 |

**老式表 + 新式 discovery 双格式**过渡：xim 引擎对老格式继续支持，新包用新格式，老包按需迁移。无破坏性。

### Phase C（半年）— 通用镜像 + 彻底退化 xim-pkgindex

**C1：xlings-res 改成 release-mirror 服务**

在 xlings-res 组织放一个**通用** workflow：

```yaml
# xlings-res/.github/workflows/mirror-on-release.yml
on:
  repository_dispatch:
    types: [release_published]   # 由 d2learn/* 发的 dispatch 触发
jobs:
  mirror:
    steps:
      - uses: gh release download / upload to xlings-res/<repo_name>
```

`d2learn/<any>/release.yml` 在 release 完之后发一次 `repository_dispatch`，xlings-res 那边自动镜像。一份 workflow，全 d2learn 包通用，加新包零成本。

或者更激进：**直接放弃 xlings-res 镜像**，让 xim 走 ghproxy / jsdelivr 这类通用 CN CDN。维护成本归零。

**C2：xim-pkgindex 退化成"包元信息库"**

不再持有任何版本数据。每个 lua 文件就是：name / description / repo / type / discovery 配置 / install hooks。所有版本动态发现。

xim-pkgindex 的角色从"版本数据库"变成"包元信息目录"，定位类似于 Homebrew 的 formula 仓库（formula 描述包，不维护历史版本号）。

## 五、推荐落地节奏

| 阶段 | 时机 | 改动范围 | 是否影响用户 |
|---|---|---|---|
| **Phase A 止血** | 立即（这周） | release.yml + 2 个 secret + 1 个 patcher 脚本 | 不影响（让 self-update 首次能用） |
| **Phase B 自描述 + self check** | 1-2 个月 | xim 引擎 + xlings.lua + 二进制 | 用户体验上升（self check 友好提示） |
| **Phase C 通用镜像 + 退化 pkgindex** | 半年 | xlings-res workflow 重写 + xim-pkgindex 全包迁移 | 透明，但是减少长期维护负担 |

## 六、风险与边界

1. **discovery 需要 GitHub API 配额** —— 未认证 60/h，认证 5000/h。xim 可缓存 latest 信息几小时，不会触发。
2. **xim discovery 第一次依赖网络** —— 用户首次 install 必须能访问 GitHub API（已是现状）。
3. **B 阶段需要保留对老式表的兼容** —— 一段时间内 xim 引擎要双格式。可加 deprecation warning，半年后逐步移除老格式。
4. **xlings-res 抓 GitHub release 的频率** —— `repository_dispatch` 触发即时；如果改成 cron，要平衡延迟。
5. **PR auto-merge 误改风险** —— xim-pkgindex 端开 required CI（pkgindex-build / 验证 lua 加载）拦下脏 patch。

## 七、补：Phase A 立即可执行清单

- [ ] 在 d2learn/xlings 仓库 secret 中加 `RES_MIRROR_PAT`、`PKGINDEX_PAT`（GitHub App 优先）
- [ ] release.yml 加 `sync-pkgindex` job（上面 yaml 模板）
- [ ] 写 `tools/sync_pkgindex.py`（或 inline python）做 lua patcher
- [ ] 在 d2learn/xim-pkgindex 配 required CI 拦不合法 patch
- [ ] 测试：手动触发一次 release（用 dry-run 模式），确认 xlings-res 出 tag、xim-pkgindex 出 PR
- [ ] 文档：`docs/release-process.md` 写下流程图

## 八、对当前 0.4.3 的处理建议

我们刚才已经手动同步过部分（v0.2.0 误污染清理、release 重发）。建议人工 backfill：

1. 把 0.4.0/0.4.1/0.4.2 的 artifact 也镜像一份到 xlings-res/xlings（让历史用户也能升级到任意旧版）
2. xim-pkgindex/xlings.lua 一次补全 0.4.0/0.4.1/0.4.2/0.4.3 + latest=0.4.3
3. Phase A 落地后这就是最后一次手动 backfill
