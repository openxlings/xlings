# 2026.9.3.1 —— 「一个文件被三个读者读成三种意思」

> 设计:`2026-09-03-project-shim-routing-vs-state-design.md`
> 计划:`2026-09-03-shim-routing-impl-plan.md`
> PR: openxlings/xlings#580

## 1. 一句话

用户报的是「项目里装的工具污染全局、项目外报错」,查下去是这个形状:

> **一个目录承担两个含义,由两个 scope 写入,被三个读者各按不同含义读。**

`~/.xlings/subos/<n>/bin/` 里的一个文件同时表示:

| 含义 | 谁写 | 谁读 |
|---|---|---|
| **路由** 这个名字归 xlings 分发 | `mirror_shim_to_global_bin`(**project scope** 的决定) | PATH / shell profile |
| **状态** 这个 subos 激活了它 | install / use(**global scope** 的决定) | `shim_dispatch`、doctor Check 2 |

shim 是 entry binary 的一个链接,不带版本、不带来源 —— **它天然只能表达路由**。是读者硬把它
读成状态,后果双向:

1. 路由文件被状态规则**解析** → 项目的工具在项目外必然报错;
2. 路由文件被状态过滤器**排除** → `has_program_kind` 查的是**全局** versions DB,而
   project scope 的安装注册在**项目** DB → **最该被报告的文件,没有一个读者看得见**。

## 4. 为什么文件必须存在

项目自己的 bin(`<proj>/.xlings/subos/_/bin`)从来不在 PATH 上,而 **cmd.exe 没有任何
cd hook** 能把它放上去。实测,不是推断:

```
command_not_found_handle:  bash ✓  bash -c ✓  sh -c(dash) ✗  make ✗  execvp ✗
相对 PATH 条目:            项目根 ✓  子目录 ✗  + PATH 劫持面
```

xlings 的主场是给 `make` / `npm` 供工具链,它们不经过交互 shell。调研的八个同类工具里,
**支持 cmd.exe 的全部**用「一个全局目录 + 按名字建文件」(proto / aqua / rustup /
pyenv-win / nvm-windows v2 / chocolatey);唯一躲开的 hermit 放弃了 Windows。

所以「零全局文件」不可达。可达的是让那个条目**派生、有主、可回收**。

## 5. 做了什么

- **`xvm::shim_table`** —— 决策层,纯函数、可单测、不碰 Config:期望集合 / 实际扫描 /
  差集 / 应用。
- **`xself::sync_shim_tables()`** —— **唯一写者**,install / use / remove 都只调它。
  project scope 下同时同步全局 subos —— 这正是 `mirror_shim_to_global_bin` 原来干的活,
  区别是现在有主(`knownProjects`)、有回收路径。
- **`knownProjects`** 只记项目**路径**。命令名在重建时从项目自己的状态文件现算:manifest
  记的是**包名**,而一个包注册哪些**命令名**只有装完才知道 —— 缓存必须在 install 时写死,
  项目一改依赖就过期,而重建会照着过期缓存把不存在的名字**重新建出来**,正是本次要消灭的
  bug 类。
- **doctor**:Check 1 和 Check 2 合并成一条 `ShimTableDrift`,**按方向分级** —— 缺文件是
  Error(有程序 active 却跑不了),多文件是 Notice(删前删后都解析到空,且老 home 上不是
  用户造成的)。`--fix` 持锁、锁内重新计划、应用差集,并**打印删了什么**。
- **宿主机透传**:当前 scope 对这个名字**毫无主张**时,把名字交还 PATH。另外两支
  (opt-in 了没选版本 / pin 了没装)是**主张**,仍然报错 —— 那两支若透传就是 pyenv 至今
  带着的静默替换。
- **安全**:只删 `std::filesystem::equivalent` 认定是 entry binary 的文件(POSIX symlink
  和 Windows hardlink 一次回答);删走 `displace_locked_file` 而不是裸 `fs::remove`。

`xvm`(1.9 MB,2025-08-30)和 `xvm-shim`(621 KB)是**旧版 xlings 的独立二进制**,不是

规则会删掉。事后确认真实 payload store 未被修改。

## 7. 被测试推翻的四条设计规则

逐条记在设计文档 §3(推翻 6-9),不悄悄改掉:

1. **期望集合不该探针 payload。** 载荷坏掉的包会静默离开表,用户拿到 shell 的
   `command not found` 甚至透传到宿主机,而不是 dispatch 那条带路径和重装命令的报错。
2. 探针本身**还错了两处**:按 `VInfo::filename` 查(dispatch 用 target 名),且要求
   **alias 包**有载荷二进制(alias 包根本不走 `resolve_executable`)。
3. **reserved 名字的保护是单向的** —— 只挡删不挡加。
4. **`xlings_binary_in_home` 少了 bootstrap 回退**(`<home>/xlings`),导致「装了、active、
   零文件」。

## 8. 顺带修的 / 顺带发现的

**修了:** `compact/xself.cpp` 的 legacy alias 判据以 `fs::is_symlink` 开头,而 Windows
上 shim 是 hardlink —— 该判据在 Windows 上恒 false,`cleanup_legacy_alias_shims` 的四个
调用点**从 0.4.8 起在 Windows 上从没生效过**,而 `report_deprecated_alias_if_match` 会让
残留的 `xim.exe` / `xvm.exe` 以 exit 2 失败。

**发现但未在本次修(建议单独开 issue):** `shim.cpp:670-687` Unix 走 `execvp`(比
proto / aqua / chocolatey 都好),**Windows 退化成 `std::system` → `cmd.exe /c`**:参数被
二次解析、Ctrl-C 和 kill 打在 shim 上而不是目标上、退出码被改写。chocolatey 这两个坑
(home#134 / home#113)分别 open 了 10 年和 8 年。修法是 `CreateProcessW` + 空的
`SetConsoleCtrlHandler`。

## 9. 兼容性

- **无迁移动作**:用户不需要跑任何命令。老 home 的死名字在下一次 `doctor --fix` 时回收;
  不跑也只是维持现状。
- **PATH / profile 不变**、release 脚本 / CI / self-contained 布局不变、无失效窗口。
- **不跨仓库**:没有新的 libxpkg 字段、没有索引格式变化、没有 recipe API 变化 ——
  `xim-pkgindex` 与其它仓库无需同步发布。
