# Release notes — 2026.8.10.1

> 前身：#519（`fix/stability-regression-recovery`）
>
> 评审与实测：`.agents/docs/2026-08-10-pr519-review-and-completion-design.md`

## 一句话

本地命令恢复即时响应（真实 71 GB home 上 `self doctor` **195.16s → 0.63s**），
并修掉三个只有在真实环境里才看得见的问题：升级会把老 SubOS 声明成它从没跑过的 runtime、
ELF 守卫把 143 个正常 payload 报成损坏、Windows 已经连续四个 HEAD 编译失败。

## 性能

真实 home（71 GB，~25 个 SubOS，887 个 XVM target）的对照：

| 命令 | 2026.8.9.2 | 2026.8.10.1 |
|---|---|---|
| `self doctor`（默认） | 195.16s | **0.63s** |
| `info gcc` | 17.357s | **0.143s** |
| `list gcc` | 7.398s | **0.132s** |
| `list` | 7.411s | **0.204s** |

做法不是加缓存或超时，而是把副作用从只读路径的调用图里移除：

- `info/list/remove lookup/sandbox lookup/doctor` 的本地查询不再隐式拉取或同步索引；
- `info <pkg>` 改为 targeted inventory，`list <filter>` 先过滤再加载；
- `self doctor` 默认只做结构/配置/绑定一致性检查，不启动 `patchelf`、`getent` 或递归子 `xlings`；
  payload/ELF 审计移到显式的 `--deep`，并可用 `--scope PACKAGE[@VERSION]` 收窄。

## 无感升级：老 home 不会因为升级而变成「不合规」

2026.8.9.1 起 `subos_info.runtime` 成为 SubOS 的 runtime 权威。问题是：
**2026.8.5.1 之前创建的 SubOS 根本没有这个块**，升级时会被常量兜底盖成 `glibc@2.44`，
而它们实际在跑 2.39。真实机器上 ~25 个 SubOS 里 22 个是这个状态。

结果本来会是：`self doctor` 变红，`xlings use glibc 2.39`（它本来就在跑的版本）被拒绝，
而唯一的提示是「新建一个 SubOS」。

本版：

- 没有记录过 binding 的 SubOS，声明来自它 **workspace 里实际 active 的版本**，而不是当前默认值；
- 已经被 2026.8.9.1/.2 盖坏的 home，`xlings self doctor --fix` 采纳实际在跑的 runtime 并明说改了什么；
- 「声明了但还没有 active」（`subos new --runtime X` 尚未安装 X）是**冷意图**，`--fix` 不会覆盖它；
- doctor 和 `use` 的提示都改成命名两条真实存在的出路：
  `xlings self doctor --fix` 采纳，或 `xlings install <runtime>` + `xlings use` 正向迁移。

**升级不需要做任何事。** 如果你的 home 已经被前两个版本盖坏，跑一次 `xlings self doctor --fix`。

## ELF loader/libc 守卫：更准，而不是更严

`self doctor --deep` 的 loader/libc 检查这一版做了三件事：

1. **PT_INTERP 也穿符号链接再分类。** 指向 SubOS 视图（symlink farm）的 interpreter 是我们自己的
   loader，之前被当成宿主 loader —— 真实 home 上 145 条告警里 **143 条是这个误报**。
2. **glibc 和 musl 不再互相比较。** musl 交叉编译器会把自己的 libdir 烘进 RUNPATH，
   glibc 二进制因此背着一个它永远不会去解析 `libc.so.6` 的目录。
3. **同一 family 内不再按 provider 过滤。** 这让「我们的 loader + 宿主 libc」这一类
   crash-before-main 第一次被看见（真实 home 上抓到 2 个 godot）。

净效果：误报 143 → 0，真实检出 +2。

## 其他修复

- `xlings subos use` 无参数列候选；但带 `--cmd` / `--sandbox` / `--shell` / `--global`
  而缺名字时**失败**，不再退出 0 却什么都不做。`--shell` 尤其重要：它的 stdout 会被调用方 `eval`。
- 安全模糊匹配：大小写敏感 exact → 唯一大小写不敏感 exact → 唯一前缀；歧义**从不**自动进入。
- `list <filter>` 不再可能是 `list` 的真子集（前置跳过判定现在也沿绑定的反向边走）。
- `remove <name>` 是「确保它没了」（退出 0，脚本可防御性重跑）；
  `remove <name>@<version>` 是「删掉这个版本」（坐标不存在时退出 1）。
- `#513`：install hook 失败时保留有界的 stdout/stderr/log transcript，不再是空的 `E_INTERNAL`。
- `#514`：依赖查找顺序为 selected/current store → project store → global store，显式、有序、去重。
- `#506`：removal 只按执行 uninstall hook 的 provider 判断 ownership，不动其他 provider 的状态与 payload。
- Windows：`subos.cppm` / `subos/sandbox.cppm` 补上 `#define NOMINMAX`。
  新增 `tests/scripts/test_windows_header_hygiene.py`，在 Linux 上就能挡住这一整类。

## 兼容性

- 状态格式不变（版本化 JSON，未引入 SQLite）。
- 全局仍然允许并存多份 glibc/runtime payload；限制的只是「一个 SubOS 当前只有一个精确 active runtime」。
- `self doctor` 的退出码语义不变；新增的 runtime finding 在冷状态下是 warning，不计入退出码。
