# 2026.9.30.1 release notes

> Related: the plan and its review rulings
> `.agents/docs/2026-09-29-download-attribution-and-install-noise-plan.md`;
> libxpkg 0.0.60 (openxlings/libxpkg#45), tinyhttps 0.3.2
> (mcpplibs/tinyhttps#19), mcpplibs/mcpp-index#490, and the index change in
> openxlings/xim-pkgindex (7-Zip, chatgpt). This record states what changed and
> what a client can observe; the post-release readings are appended in §4.

## 1. Changes

| Item | Change |
|---|---|
| A failed download says whose fault it was | `xlings::tinyhttps::FailureKind` {Source, Transfer, Local, Cancelled}, decided once in the xhttp wrapper. What landed on disk is compared with what the transfer reported before the content is judged. Source (complete file, wrong content; HTTP ≥400): next candidate, the host is demoted. Transfer (short, reset, stalled): retried on a later round. Local (the file is shorter than what was received, the destination cannot be opened, the disk cannot hold the body): the download stops, no host is demoted, `E_DISK_FULL`, the free space is in the message |
| Space check | At the first Content-Length a disk that cannot hold the rest stops the transfer before it is spent. A free-space figure that cannot be read never refuses. `XLINGS_DOWNLOAD_SPACE_CHECK=off` |
| One error per failed download | The download panel's ✗ row stays; the install report carries one error with the reason (and the code and hint), and no longer adds a reasonless `failed:` line or `download artifact missing` |
| Hook commands write to a log | The commands an install / config / uninstall hook runs write to `<home>/logs/hooks/<ns>-<name>@<version>.<hook>.log` (libxpkg 0.0.60 `ExecutionContext::hook_log`), rewritten each run. A failure prints the last 20 lines and the log's path. `XLINGS_HOOK_OUTPUT=inherit` or `-v` give them the terminal again (never in the interface or the TUI). A recipe command that must reach the terminal passes `system.exec(cmd, { tty = true })` |
| Heartbeat | A hook running for 15 s prints `… <pkg> <hook> hook running <t>: <last log line>`, then every 60 s; the interface gets `progress` phase `hook` (protocol 1.5). `XLINGS_HOOK_HEARTBEAT=<first>:<every>` or `off` |
| `use` / `self update` | `use` announces a switch only when something moved: the target and every member of its release already at the selected versions is a silent re-materialization. `self update` on a current home ends with `xlings is already at <v> (latest)` instead of two `xlings -> <v>` lines |
| `info` | A recipe written `deps = { ... }` shows one `deps` row, not the same list as `runtime deps` and again as `build deps` |
| Build | libxpkg 0.0.60 through the mcpplibs index |

## 2. Client-visible differences

- A full disk during a download is reported as a local failure with the free
  space, once, and no mirror is tried; before, it was `sha256 mismatch`, the
  host was demoted for the session and its retries were skipped.
- Install output no longer contains what a recipe's commands print (7-Zip's
  listings during qt, chatgpt, …). It is in `<home>/logs/hooks/`.
- A failing hook's error shows 20 lines of output, not up to 16 KB.
- Interface protocol 1.5: `progress` phase `hook`; a download that failed
  locally carries `E_DISK_FULL`; one `error` event per failed download.
- On the interface, stderr no longer carries the hook commands' output as
  `[stray stdout]` lines.
