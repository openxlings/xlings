# 2026.9.28.2 release notes

> Related: xlings#617, #624, #626, #627; the ecosystem design of 2026-09-28
> (mcpp-community/mcpp `.agents/docs/2026-09-28-ecosystem-design-and-optimisation-plan.md`,
> WS4, WS5 and WS6). This record states what changed and what a client can
> observe; the post-release readings are appended in §4.

## 1. Changes

| Item | Change |
|---|---|
| Progress is data (WS4, protocol 1.3) | `download_progress` carries the files, their bytes, the elapsed time and a `stream` id (`index:<name>` for an index fetch, `install:<n>` for one batch of package downloads). A producer sends at most one event per 100 ms per stream, does not repeat an unchanged state, and always sends the final one. An index artifact fetch sends one finished event when it completes, whether or not its size was known during the transfer. `prevLines` is deprecated and always 0; it stays until 2.0 because a minor version only adds |
| The renderer owns its frames (WS4) | The CLI keeps each stream's frame state: the line count of its last frame, the time it was drawn, and the items it has announced. On a terminal it draws at most one frame per 100 ms, plus the last. Off a terminal it prints one line when a download starts and one when it finishes. The downloader no longer hides the cursor or chooses a cadence by the destination |
| One rebuild per `update` (WS6) | `update` takes the catalog without its implicit first build and performs only the forced rebuild, so each index's `pkgindex-build.lua` runs once |
| A store hit is named (WS6) | When the version `update` moves to is already in the store, the output is `<pkg>@<v> is in the store` and then `active: <a> -> <b>`, instead of "is already installed" followed by "upgraded". `install --use` of a stored version prints the first line as well |
| A home is declared (WS5, #617, #624) | `self init` writes `<home>/.xlings-home` (a random id and the path at creation). One predicate, `home_identity::is_home`, answers "is this a home": the marker, or else the legacy layout of a directory that is not a SubOS of another home. `resolve_owner_home` walks to the nearest such home, so a SubOS that contains a `subos/` of its own is no longer taken for a home (#617). `normalize_subos_paths` leaves unchanged a path that continues into a home nested below a `subos/<name>/` segment, and applies the SubOS rule to the nested home's own segment instead (#624) |
| Migration | A home without the marker gains it on the first CLI command of this version. A home on read-only storage keeps working without it, is recognised by its layout, and `self doctor` reports a `home marker` notice |

## 2. Client-visible differences

- Off a terminal, a download prints two lines instead of a frame every five
  seconds (install) or a frame per received chunk (index). A CI log of
  `xlings update` measured 769 progress lines for one index on 2026.9.28.1 and
  2 on this version.
- An interface client sees `stream` on every `download_progress` event and at
  most ten events per second per stream. A 1.2 client that reads `prevLines`
  reads 0, as it already did for the index download.
- The structural `xvm::is_home_root` is removed; its readers use
  `home_identity::is_home`.
- `update` of a package whose target version is already in the store prints
  `active: <a> -> <b>` where it printed `upgraded <pkg>: <a> -> <b>`.

E2E-01 on Windows (`bootstrap_home_test.ps1`) renamed the portable home with
`Move-Item` immediately after `self init`. The rename failed on this branch's
first run, 0.2 s after `init ok`, with "You do not have sufficient access
rights"; the same failure occurred on 2026-09-14 on a branch that did not touch
init, and passed on that branch's next run. A handle held inside the fresh tree
(an on-access scan of the new executables) makes the rename fail for a moment.
The test now renames with `[IO.Directory]::Move`, which either renames or leaves
the tree intact, retries for at most 10 s, and on failure names the processes
running from the tree.
