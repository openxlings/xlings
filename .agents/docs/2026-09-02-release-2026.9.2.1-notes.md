# 2026.9.2.1 — 版本键的拼法由身份决定,不再随 `index_repos` 的排列翻转

> 方案与根因:`2026-09-02-version-key-namespace-flip-plan.md`(§0–§6 诊断,§10 实施中被推翻/修正的判断)。
> 本文只记**发布了什么、怎么验证的、还剩什么**。

## 一句话

`version_namespace_()` 是 `#575` 漏掉的最后一处"数组第 0 个条目 = 官方索引"的位置特权。
`xim` 被挤下 0 号位后,同一个包的版本键从 `2.1.222` 变成 `xim:2.1.222`,老记录再也查不到:
`remove` 拒绝、多 subos 只 detach 的分支被跳过、`use` 挂到无主重复记录、`install` 以
`xvm-group-conflict` 楔死并甩锅 recipe。这次把判定改成认名字,读侧双向宽容,写侧沿用磁盘上
已有的拼法,再给已经产生的重复键一条 doctor 修复路径。

## 真机验证(`/home/speak/.xlings`,全程 `xlings subos use default --sandbox --cmd "…"`)

这台机器就是报告这个问题的 home:`index_repos = [scode, dsh, xim]`,81 个 subos,
1635 个 target。升级前状态文件已备份。

| # | 命令 | 结果 |
|---|---|---|
| a | `xlings --version` | `2026.9.2.1` |
| b | `xlings self doctor` | 16 行 `duplicate version key`(按 release 折叠)、10 条 `incomplete install` |
| c | `xlings self doctor --fix` | **merged 240**、1 个 subos 的引用被改写、healed 67、孪生对归零 |
| d | `xlings self doctor` | `duplicate version key` **0 行** —— 收敛 |
| e | `xlings remove claude@2.1.222 -y` | `✓ detached — payload kept — still used by gfxbuild`,payload 与 gfxbuild 的引用都在 |
| f | 10 个被楔死的包 | 全部 `already installed`,`incomplete` 戳剩 **0** |
| g | `xlings use perl@5.44.0` | `perl -> xim:5.44.0`(有主记录) |

**合并后的不变量(独立核查,不看 doctor 的自述):** 扫描全部 81 个 subos 的
`active` / `installed[]`,**指向已删除记录的引用 0 条**;孪生对 0。

**归因过的一处:** `--fix` 还删了 2 条**非 xim** 命名空间的记录
(`glibc@local:2.44.2`、`ldd@local:glibc-2.44.2`)。那是 doctor **既有的** broken-payload
清理干的 —— 日志原文 `its payload is gone and nothing can restore it`,
且 `data/xpkgs/local-x-glibc/2.44.2` 在盘上确实不存在。孪生谓词**没有**匹配它们
(路径不同:`local-x-glibc/…` vs `xim-x-glibc/…`),与本次改动无关。
副作用是留下一条 `binding state: release local:glibc@2.44.2 does not resolve` —— 见下。

## 另开的 issue(都不在本次范围)

- **#578** `remove fd`:只有一条无主裸记录、不在任何 subos 里,CLI 却把名字解析成索引的
  latest;且 `hasSelection == false` 时 versionless 删除即使只有一个存储版本也从不解析。
  与排列无关,发布版同样失败。
- **#579** `self update` 的三句假消息:`entry binary DOWNGRADED` 把带命名空间的键
  (`xim:2026.9.2.1`)喂给了要裸版本号的比较器;末尾的 `nothing was upgraded` 读的是切换前的快照。
  升级本身是成功的。
