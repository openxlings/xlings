# 2026.9.2.1 — 版本键的拼法由身份决定,不再随 `index_repos` 的排列翻转

> 方案与根因:`2026-09-02-version-key-namespace-flip-plan.md`(§0–§6 诊断,§10 实施中被推翻/修正的判断)。
> 本文只记**发布了什么、怎么验证的、还剩什么**。

## 一句话

`version_namespace_()` 是 `#575` 漏掉的最后一处"数组第 0 个条目 = 官方索引"的位置特权。
`xim` 被挤下 0 号位后,同一个包的版本键从 `2.1.222` 变成 `xim:2.1.222`,老记录再也查不到:
`remove` 拒绝、多 subos 只 detach 的分支被跳过、`use` 挂到无主重复记录、`install` 以
`xvm-group-conflict` 楔死并甩锅 recipe。这次把判定改成认名字,读侧双向宽容,写侧沿用磁盘上
已有的拼法,再给已经产生的重复键一条 doctor 修复路径。

### 顺带量到的、不在本次范围的

- **`remove fd`**(fd 只有一条无主裸记录 `10.4.2`,不在任何 subos 的 workspace 里):
  CLI 把它解析成索引里的 latest `10.5.0`,于是走到 `registers no xvm version` →
  `removal operation has no exact version`。**与排列无关**,发布版在 `[xim,…]` 下同样失败。
  是另一条缺陷:"只有一个存储版本的 versionless 删除"在 `hasSelection == false` 时从不解析。
  记在这里,另开 issue。

## 升级路径

老 home 不需要做任何事:D1 让新注册回到裸键,D3 让重装沿用已有拼法,D2 让翻转期间写下的
`xim:` 键仍可达。`xlings self doctor` 会把翻转期间产生的重复键报出来,`--fix` 一次合并。
被楔死的包(`incomplete` 戳)直接 `xlings install <pkg>@<ver>` 装回去。
