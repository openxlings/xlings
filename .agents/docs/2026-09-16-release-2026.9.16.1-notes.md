# 发布 2026.9.16.1 —— 区域是顺序,刷新有界

> 设计:`2026-09-16-issue598-region-chain-design.md`;PR openxlings/xlings#601。
> Issue:#598(修)、#599(修)、#600(答复 + 顺带补两处真实缺口)。
> 状态:**已发布**(c4ebafb;xim-pkgindex#847)。

## 1. 一句话

配置里的区域对象 `{"GLOBAL":…,"CN":…}` 以前被读成「按 mirror 选一个」,读完另一个就不存在;
现在它是一条**有序候选链**——mirror 决定顺序,不决定集合。同一轮把索引刷新的每个网络动作
都加上界,并给一次 `xlings update` 一个总预算。

## 2. 交付

见 PR #601 描述。要点:

- `parse_region_chain` 成为唯一回答者(此前配置层三处各自实现「选一个」);
- `IndexRepo::artifactBases`(有序 + 带区域标签)取代 `artifactBase`,**一个拼写**;
- pointer / asset 的候选 URL 覆盖链上每个远端 base;`BaseOverride` 变成有序条目,本地 base 也成链;
- **pointer 文件名按 base 各自推导**(两个镜像不必同名)—— 这一条是我自己的实现缺陷,由新增的 e2e 场景 F 抓出来;
- `xim.index-base` 同样成链;`xim.mirrors.index-repo` 只取首个(它命名 git remote,一个 clone 只有一个 origin);
- 区域对象往返不丢(`xim-indexrepos.json`);
- **子索引可以声明自己的 artifact**(`xim-indexrepos.lua` 里 `["artifact"]`,字符串或区域对象)—— 此前 artifact 这个默认机制只有顶层 `index_repos` 能用;
- `xlings index list` / `--json` / interface `list_repos` 列出会按什么顺序试;
- #599:git 拿到 `GIT_HTTP_LOW_SPEED_*` + `GIT_TERMINAL_PROMPT=0`(操作员已设的不覆盖),索引 HTTP 收紧到 10s/120s,一次刷新 300s 预算,超出即**跳过并说出来**。

新增 e2e:`custom_index_artifact_test.sh` F/G,`E2E-113 index_network_bounds_test.sh`;单测 56 套。

## 3. 实施中被推翻的判断

1. **「互为镜像的仓库同名,pointer 文件名可以沿用首选的」** —— 场景 F 当场证伪(去 `myindex/` 里找 `no-such-base-pointers.json`)。改成按 base 各自推导。
2. **「G 可以用本地 http 服务器做穿透验证」** —— 下载层只支持 HTTPS(`Only HTTPS is supported`),没有可用的本地 https 夹具。G 改为断言**两个 base 都被尝试过**,这正是 #598 与其修复之间唯一的差别。
3. **「#599 的 11.5 分钟是 HTTP 路径」** —— HTTP 早就有 30s 连接 / 30s 读 / 停滞看门狗;`sync_repo` 也早有 3s TCP 预探。真正无界的是 **git 的传输**,而预探恰好放行了「握手已完成、随后沉默」的连接。
4. **「#600 是 mirror 没有为已注册子索引选镜像」** —— 真机量出三个子索引全带 artifact 标记、无 `.git`,即走官方分区有序服务器(CN 下 GitCode 优先)。json 里的 GitHub URL 是**声明来源**(兼 git 回落),不是刷新走的路。真实缺口是另外两处(子索引不能声明 artifact、路径不可见),已一并修。
5. **「`XLINGS_UPDATE_TIMEOUT` 在 e2e 里没生效」** —— 是测试自己的问题:`self init` 也会同步,于是待测的 `update` 面对的是已经克隆好的子索引,什么都没做。测试读的是 init 的日志。
