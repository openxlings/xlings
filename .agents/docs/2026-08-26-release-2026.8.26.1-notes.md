# 2026.8.26.1 —— 「一个发布走的时候,把自己的文件带走」

> 设计:`2026-08-26-declared-file-assets-removal-design.md`
> 上一轮:`2026-08-22-release-2026.8.22.4-notes.md`
> PR: openxlings/xlings#562、openxlings/xim-pkgindex#689
> Issue: openxlings/xlings#423

## 1. 一句话

`xvm.files` 声明的资产从 2026.7.27.0 上线起就没被任何卸载路径回收过。
不是"少了一个分支",是**同一个问题有三个回答者,只有一个答对**——
而修的过程中,**九条我自己的判断被实测推翻**,其中四条是这一轮自己制造又自己抓到的。

## 2. 用户会立刻感觉到的

| | 改前 | 改后 |
|---|---|---|
| `xlings remove glib` | 274 个头 + 5 个 `.pc` 留在 sysroot | 随发布回收,空目录一并清掉 |
| `xlings remove <pkg>`(别的 subos 还在用) | **一个都不清**,而且留下的是**能用的**链接 | 本 subos 干净,别的 subos 一条不少 |
| `xlings use <pkg> <旧版本>` | 新版本多出来的资产原地不动(两个发布混在一起) | 回收,不再列成 stranded 让你自己处理 |
| `xlings self doctor` | 真实 home 上 110 条泄漏,报告 **0 条** | 全部报出,按 payload 折叠成几行 |
| `xlings self doctor --fix` | 看不见就修不了 | 悬空归零,空目录回收,`usr/include` 保留 |
| `<scsi/sg.h>`(装了 glibc) | **不存在** | 存在(索引侧 #689) |

## 3. 三个回答者

问题是「这个发布往 subos 里放了哪些资产」:

| 谁在问 | 怎么问 | 结果 |
|---|---|---|
| `xlings use` | 遍历 `selection->members`,逐成员查 | **对** |
| detach 路径 | 拿**包名**去问 `file_placement` | 恒空 |
| 完整卸载路径 | **根本没问** | 无 |

资产注册成**自己的 target**,名字叫 `<pkg>.files.<n>`,`<n>` 是 libxpkg 的 Lua
计数器在安装时按声明顺序生成的。这个名字**永远不等于包名**——所以第二个
回答者不是"漏了一种情况",是构造上不可能对。

修法是把它收敛成一个:`release_file_placements()` 是唯一的成员遍历入口,
`reclaim_declared_assets()` 是唯一的回收策略,四条路径共用。

## 4. 危险的是没人测过的那一半

- **完整卸载**(payload 删掉)留下**悬空**链接:难看、会累积,至少找得到。
- **detach**(别的 subos 还在用)留下**能用**的链接:编译器继续用一个"已经卸载"
  的包的头文件,任何找坏链接的扫描原理上都看不见。

真实 home 上两种都有:`libxkbcommon` 的 payload、DB 记录、workspace 记录全没了,
只剩 6 条符号链接躺在两个 subos 里,已经无法归因到任何包。

## 5. 回收策略:一份,四个调用方

| 目的地状态 | 动作 |
|---|---|
| 没有任何 active 声明 | 删除 + 回收只为它存在的空目录(保留 `usr/include` 这类两段路径) |
| 有 active 声明(可能是别的包) | **重新指向**那个发布 |
| 链接指向 payload store 之外 | 保留 + 告警(别人换掉的,不由卸载裁决) |

第二行是必须的:真实安装上 `usr/include/scsi` 同时被 glibc 和 linux-headers
声明,**"有幸存者就跳过"和"删掉被移除方声明的"两个都是错的**——前者把泄漏
换成悬空,后者把一个还装着的包的头文件拿走。

回收由**元数据**驱动,不是"是不是悬空符号链接"。Windows 上资产是硬链接或副本,
那个判据恒假,而且硬链接会让旧内容在 payload 删除后继续活着。

## 6. 写穿 payload:实测过,真的会

`place_asset` 里 `create_directories` 把**目录符号链接**当成"已存在"。所以往
别人的目录资产里放叶子,文件会落进**对方的 payload** —— 一个所有 subos 共读、
没有任何卸载会清理的地方。

写了五行 C++ 空跑验证过,`sg.h -> /etc/hostname` 确实落进了 payload 目录。

护栏是**无损转换**而不是拒绝:目录链接换成真目录,原 payload 每一项各补一个
链接。这样两个包共享一个目录时,**无论谁先装都不丢东西**——拒绝会把索引侧的
粒度迁移直接堵死。

## 7. doctor 看不见的原因,写在它自己的注释里

```cpp
// 只有扫描才能看见它们。扫描很便宜(header farm 是每个顶层条目一个链接)。
```

`declare_headers`(目录粒度)时代这句话是对的。`declare_headers_tree`
——为 X11/graphics 栈引入、**29 个 recipe 在用**——把它变成了**每个文件一个链接、
嵌套 2-4 层**。扫描的形状没跟着改,`etc/`/`share/` 更是从来没扫过。

真实 home 全量实测 **110 条**泄漏(`gfxbuild` 98 / `default` 6 / `current` 6 /
`xkbverify` 6),`self doctor` 报 **0 条**。

下面这组是**切片**(`slice-real-home.sh`,只含 `default`/`current`,7 条)上的
前后对比 —— 数字比 110 小是因为切片范围小,不是修复只清了 7 条:

```
修复前二进制   dangling sysroot link × 0        ← 深度 1 看不见
修复后二进制   2 行,覆盖 7 条链接                ← 按 payload 折叠
耗时           1.32s                             ← 无性能回归
--fix 之后     悬空 0,空目录回收,usr/include 保留
verify-untouched  真实 payload store 未被改动
```

## 8. 这一轮自己制造又自己抓到的四个

**其一,`use` 的回收是个 no-op,而我的单测放过去了。**
回收的判据是"还有没有 active 的声明",而搁浅的成员**仍然 active**——
它对自己回答"有",链接被**重新指回**刚离开的那个发布。单测只断言了 plan,
plan 是对的,效果是零。修法是先取消激活再回收;测法是 e2e 跑真命令看 sysroot,
它对修复前二进制**和中间那版 no-op** 都失败。

**其二,e2e 的对账判据本身不足以证伪 detach 那一半。**
拿修复前的二进制跑,对账**通过**了——旧行为把 `.files.N` 也留在 workspace
里当 active,于是泄漏的链接按对账的定义就是"已声明"。
**一个 bug 能满足的判据不是判据。** 补了一条不依赖元数据的断言。

**其三,索引侧的迁移辅助让新客户端表现更差。**
第一版 `unwrap_directory_asset` 只是 `rm` 掉陈旧链接,实测在**新客户端**上
把对方 6 个头文件扔了——而客户端本来会无损保留。改成在 Lua 里做同款无损解包。

**其四(最严重),我引入的回收把文件从 payload 里删掉了。**
解包会把 payload 里的**子目录**整个链过来,于是回收
`usr/include/scsi/fc/fc_fs.h` 时路径**穿过那个链接解析进了 payload**——
detach 一次,linux-headers 的 `include/scsi/fc/` 就空了,而那个包还装着、
还在另一个 subos 里 active。入口方向写穿只是多一个文件,出口方向写穿是**删**。
两处都修:回收在祖先里见到 payload 链接就拒绝并告警;解包改成递归,目录建成
真目录。**fixture 测不出这个** —— 只有真实包(`scsi/fc` 是子目录)才有这个形状。

另外五条被推翻的判断记在设计文档 §8.2,包括"doctor 的应有集不完整"(其实
早就完整)和"全量对账可以进 `--fix`"(实测会删掉 463 条**正在工作**的链接,
那是另一个缺陷)。

## 9. 索引侧(#689)

`declare_headers` 加 `opts.merge`:列出的名字改走逐文件声明。
glibc / linux-headers 同一次发布各加 `merge = {"scsi"}`。

**原计划说索引改动必须等客户端发布之后。实测推翻了**:索引侧自带
`unwrap_directory_asset`,老客户端 2026.8.22.4 装新索引同样安全。

| 安装顺序 | `usr/include/scsi` | payload |
|---|---|---|
| linux-headers → glibc | 真目录,9 个文件 | 未被改动 |
| glibc → linux-headers | 真目录,9 个文件 | 未被改动 |
| 陈旧链接 → 装 glibc(迁移路径) | 真目录,9 个文件 | 未被改动 |
| **老客户端,两个都装** | 真目录,9 个文件 | 未被改动 |

## 9.1 真实生态验证(隔离 home,真实包,2026.8.26.1)

不是 fixture,是索引里的真包:

```
装 glib            426 条链接(274 头 + 9 pkgconfig + libs)
remove glib        指向 glib payload 的链接 0 条,glib-2.0 目录已回收,usr/include 保留
装 libxkbcommon    6 条(这个配方没有手写 rm,所以它证的是客户端在回收)
remove libxkbcommon 6 → 0,xkbcommon 目录已回收
detach linux-headers(second subos 还用着)
                   default 残留 0 条;second 仍 9 条;payload include/scsi/fc/ 四个头完好
沙箱内             xlings --version → 2026.8.26.1(先确认版本再动手)
sysroot 头可达性   scsi/{sg.h,scsi.h,scsi_ioctl.h,scsi_netlink.h,scsi_bsg_fc.h,fc/fc_fs.h}
                   六个全部通过语法检查,来源分别是 glibc 3 个 / linux-headers 3 个
```

`fc/fc_fs.h` 那一条是特意加的:它就是 §8「其四」里被删掉的那批文件所在的子目录。

## 9.3 发布产物本身验过

不是"用我的构建验",是**解开 tarball、用它自己的 `self install` 建一个隔离
home、再用那个 home 里的二进制跑**——这是唯一能证明将要分发的东西可用的做法
(一个二进制指着空 `XLINGS_HOME` 只会建出半个 home)。

```
tar -xzf xlings-2026.8.26.1-linux-x86_64.tar.gz && ./bin/xlings self install
  版本 2026.8.26.1,3 个 shim
install libxkbcommon    6 条链接
remove  libxkbcommon    残留 0 条,xkbcommon 目录已回收
self doctor             0 条悬空
```

## 10. 判据

**不要用 `[ -e ]`**——它跟随符号链接,payload 删掉之后一个**仍然存在**的悬空
链接会读作"不存在"。这就是这个缺陷活到今天的原因。

用 `-xtype l`;而 detach 那一半链接不悬空,只能**对账**:

```
subos 下指向 payload store 的链接集  −  本 subos active 声明的 fileDst 集  =  ∅
```

## 11. 升级后要做什么

存量泄漏没有元数据可以归因(DB 和 workspace 记录都已被清走),靠 doctor 兜底:

```bash
xlings self doctor --fix
# 每个非活跃 subos 单独跑一次:
XLINGS_ACTIVE_SUBOS=<name> xlings self doctor --fix
```

## 12. 本轮没做

- **未声明但可用的 sysroot 链接**(实测 646 条):资产被放进了没有声明它的
  subos。**另一个缺陷**,清掉会删除正在工作的头文件,独立 issue。
- **重新注册后不再声明的目的地不被回收**:记录与链接都留着。属于注册层,
  与 `detachedLegacy` 的既有语义冲突,需要单独设计。
- **`cleanup_removed_xvm_library_artifacts` 的"有幸存者就跳过"**:同样会把
  泄漏换成悬空,影响另一批状态,拆开走。
- **`xvm::remove_asset` 仍用 `remove_all`**:新代码一律 `fs::remove`;
  Windows junction 在 `remove_all` 下是否跟随**未验证**,不在没测过之前动它。
